# 流式异常恢复实现与验收记录

## 实现范围

- `ChatGenerationCoordinator` 由应用持有，页面只订阅；切换会话继续生成，每个会话一个请求、全局最多三个。请求开始固定配置和上下文，后续上下文排除未完成助手回复。
- OpenAI 使用 `[DONE]` 确认协议结束，也接受已收到 `finish_reason` 后的正常 EOF；尾部最多等待两秒。Anthropic 使用 `message_stop`。缺少结束信号的 EOF 进入中断。
- 字节空闲、无正文或思考进展、总时长默认分别为 60、180、600 秒。取消传到 URLSessionTask，并等待 SSE 生产任务退出；已确认成功后的清理取消不能改写成功终态。
- 用户消息、助手占位、会话时间事务提交后才请求。每秒保存有变化的完整快照，停止、结束、进入后台立即排队保存；生成身份和快照序号拒绝旧写入。
- 冷启动迁移后修复遗留 `streaming`；数据库打开失败展示重试，不退回内存库。保存失败保留内存内容、停止生成并提供重试保存。
- 后台继续最多 20 秒或系统更早到期，申请失败立即中断；失焦不取消，前台不重发。后台暂停聊天增量排版，前台从完整快照恢复。
- 停止立即关闭事件入口；重新生成在首个非空正文或思考到达前保留原回复，之后同步替换两者。草稿和阅读位置按会话保存在本次进程内；只有末尾助手消息可重新生成。
- 日志只记录结束原因、耗时及保存失败类别，不记录 API Key、正文或思考。

## 审查中修复的交叉竞态

1. 停止后立即发送或重新生成，等待上一轮保存结果，保存失败不能覆盖尚未保存的内存回复。
2. 准备事务与删除并发，删除失败恢复数据库当前生成身份；覆盖首次发送、已有回复后发送和重新生成三个分支。
3. 新轮首段只有正文时同步清空旧思考视图。
4. 发送事务等待期间编辑的新草稿不被旧请求成功回调清空。
5. 用户停止和后台到期的原因不被模型结束原因覆盖。
6. 协议尾部计时器与 reader 清理竞争时，已确认成功不能再抛出取消错误。

## 验收边界

- 磁盘库重开验证了恢复逻辑，不能等同于真实进程强杀测试。突然终止只能恢复最后一次成功提交的快照，最近尚未保存的增量可能丢失。
- 系统后台挂起、锁屏、强制结束须在脱离调试器的真机验证；本次没有可用真机验收结果。
- 真实服务商、真实断网/弱网与 iOS 16 runtime 尚未执行端到端验收。协议验证使用可控服务及模拟器，不使用用户凭据。
- 草稿与阅读位置只保证跨页面返回，不承诺跨进程恢复。生成写入移到串行后台队列；既有会话创建、重命名及部分读取仍使用原有同步仓储接口。

真机验收步骤：生成过程中切后台并在 20 秒内返回，确认继续且无重复；后台超过预算或系统提前到期，确认部分内容与中断提示；锁屏后返回检查按钮；生成并等待周期保存后强制退出再启动，确认部分回复与“上次生成已中断”，随后可正常发送和重新生成。记录系统版本、结束原因及耗时，不记录正文或凭据。
